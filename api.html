class aamaslib.ca.envs.BaseCellularEnvironment(config: dict, env_shape: str = 'grid', update_rule: UpdateRule | None = None, render_mode: str | None = None, renderer=None)

Bases: ABC

This abstract class provides the foundation for cellular automaton environments, with customizable update rules, grid configurations, neighbourhood types, and boundary conditions.

Features:

  • YAML configuration loading

  • Grid initialization from configuration

  • Flexible neighbourhood definitions (Moore, Von Neumann, custom)

  • Multiple boundary condition options (dead, periodic, reflective)

  • Abstract step method for specific CA implementations

  • State management and inspection

  • Built-in rendering support

Algorithms/Update Rules

Cellular automaton update rules for cellular automaton simulations. This module provides a framework for defining cellular automaton update rules, which determine how cells evolve from one generation to the next based on their current state and the states of their neighbours. The module includes: - An abstract base class for defining update rules - A configurable custom rule implementation - A factory function to create rules from string notation - A registry of common rules Classes:

UpdateRule (ABC): Abstract base class for cellular automaton update rules CustomRule: Configurable rule with custom birth/survival conditions

Functions:

create_rule_from_string: Create rule from string notation (e.g., ‘B3/S23’ for Conway)

Constants:

RULE_REGISTRY: Dictionary of pre-configured common cellular automaton rules

Base Algorithm Interface Module

This module defines the abstract base class that navigation algorithms must implement to ensure compatibility with the grid environment system.

Bases: ABC

Abstract interface for all navigation algorithms.

abstractmethod get_action(state: Any, training: bool = True, action_mask=None) → int

Select an action given the current state.

This is the core method that all algorithms must implement. The method should return an action index corresponding to the environment’s action space (0=up, 1=right, 2=down, 3=left for grid environments).

Parameters:

  • state (Any) – Current state representation. This can be: - int: Discrete state index (for RL algorithms) - Tuple[int, int]: Position coordinates (for search algorithms) - Dict: Complex state observation - Any other state representation the algorithm requires

  • training (bool) – Whether the algorithm is in training mode. - True: May use exploration strategies (e.g., ε-greedy) - False: Should use exploitation/greedy policy

  • action_mask (np.ndarray, optional) – Boolean array indicating valid actions. If provided, the algorithm should only select from valid actions.

Returns:

Action index (0-3 for cardinal directions in grid environments)

Return type:

int

get_state() → Any

Retrieve the current internal state of the algorithm.

This method enables serialisation of the algorithm’s learned parameters or internal state for saving to disk, checkpointing, or transfer learning.

Common return values: - Q-learning: Dictionary containing Q-table and exploration parameters - Search algorithms: None or configuration parameters - Others, for example, neural networks: Model weights and hyperparameters (Not covered)

Returns:

Serialisable representation of the algorithm’s internal state.

Should be compatible with set_state() method. Returns None if the algorithm has no internal state to save.

Return type:

Any

Note

The returned state should be serialisable (e.g., using pickle) and contain all information necessary to restore the algorithm to its current state.

update(*args, **kwargs) → None

Perform a learning update after observing a transition.

This method is called after each environment step to allow learning algorithms to update their internal parameters. The method signature uses *args and **kwargs to accommodate different algorithm requirements.

Common usage patterns: - Q-learning: update(state, action, reward, next_state, done) - Policy gradient: update(trajectory_data) - Search algorithms: No update needed (method does nothing)

Parameters:

  • *args – Variable positional arguments specific to the algorithm

  • **kwargs – Variable keyword arguments specific to the algorithm

Returns:

None

Note

This method is optional and defaults to no-op. Search algorithms and other non-learning methods can ignore this method.
